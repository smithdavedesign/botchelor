# Audit — 2026-10-21

A full pass over the repository as it stands on `main` at `55fc605` (PR #518), done in the same session that worked
the open `agent-feedback` backlog (#413–#515). The 2026-10-14 audit is [audit.md](audit.md); this one doesn't repeat
what it found, it says what has changed since and what the repo looks like now. `BUILD.md` and `ROADMAP.md` stay the
authoritative status pages.

**Method.** Read every file the backlog touched (`lib/mcp.ts`, `lib/own-date.ts`, `lib/swipes.ts`, `lib/texting.ts`,
the episodes route, the loop scripts, the docs), ran the typecheck and the full suite before and after the changes,
measured the MCP tool list, ran `npm audit`, and read the CI, middleware, session, safety and limits code. Then ran
the loop's arena locally with the stub model and played it as an uninstructed agent
([mcp-simulation-2026-10-21.md](mcp-simulation-2026-10-21.md)).

## 2. What's strong

- **The invariants hold and are tested.** The engine decides endings (never a model, never money); a performer only
  sees its own character's soul; private dates stay offline; points can't be bought. Each has a test, and the MCP
  layer is a thin adapter over the same API handlers people use, so agents inherit every guard.
- **Security posture is as the 2026-10-14 audit found it, plus two fix PRs (#508, #509).** Signed `HttpOnly`
  sessions, parameterised SQL everywhere, Stripe signature over the raw body, constant-time admin password
  (`safeEqual`, used by every `app/api/admin/*` route), a strict content filter, hashed-IP rate limits on date starts
  and reviews, a kill switch and a daily paid-model cap. The MCP endpoint is CORS-open by design (identity is an
  argument, never a cookie) and body-capped at 64 KB.
- **The self-improving loop works as a feedback source.** 85 issues in two days, each with a quote, the code
  location and a proposed fix; most were right about where the problem lived. Of the 79 non-policy issues, 9 were
  already fixed on `main` by the time this pass started (the loop's own fixer had got there), which is the loop doing
  its job.
- **Documentation is unusually honest**: costs, kill criteria, "no purchase yet", what the owner still has to do.

## 3. Findings

Ordered by how much they matter. Each says where it lives and what to do.

### 3.1 Operations

1. **CI has not run since 2026-10-19.** GitHub Actions minutes ran out (`docs/costs.md`: "reset around Nov 1"), and
   the Actions API confirms it: every `CI` run from #510 to #518 (runs 424–431) is `completed: failure` within 2–4
   seconds, with one job that has no steps and no log (a job that never started). `ci.yml` is the only check that runs
   the tests, and PRs #510, #511, #516 and #518 were merged with it red, so since the 19th `main` has been protected
   by local runs and Vercel's build (which proves it builds, not that it works). This is known and documented
   (`docs/history/2026-10-19-to-21.md`: "each merges after local tsc and the full vitest run pass, since GitHub
   Actions minutes run out until ~Nov 1"), and the commit messages do report local suites (1625/1625, 1627/1627), so
   nothing is known to be broken. But the loop's fixer "merges once every check is green", so it cannot have been
   merging on CI either, and a red check that everyone ignores is worse than none. **Do now:** require the `test` check in branch protection
   (so a red CI blocks a merge rather than being ignored), and buy minutes or move the job to a cheaper runner until
   November. The free plan's 2,000 minutes went on a ~10-minute job × ~2 runs per PR × ~100 PRs; `paths-ignore` for
   docs-only pushes would stretch them.
2. **The arena and the signed-in e2e share a port** (reported by the mobile-audit agent: a signed-in pass seeded into
   the nightly sim's app, 10–20¢ of paid dates, and run `2026-10-20-2347`'s ratings are tainted). `arena.mjs` now
   refuses a busy port and stops when its server dies (#516). Issue filed with the loop's run log: the triage prompt
   should also skip reports whose `world.json` doesn't match the run.
3. **The loop runs on the owner's laptop** (launchd at 06:10, keychain keys, `~/.botchelor-loop`). It's documented as
   a choice, but it means no run when the laptop sleeps, and a port collision with anything else running there.
   Worth a line in the loop doc on how to tell a missed run from a quiet one (`run_started` events exist; nothing
   checks that one happened).
4. **Vercel build minutes are most of the Vercel bill** (~$17 of the $20 credit in October, `docs/costs.md`), because
   every merge deploys and the loop merges up to 3 PRs a morning plus the owner's own. Batching the fixer's PRs into one
   deploy, or ignoring docs-only commits for builds (`vercel.json` `ignoreCommand`), would halve it.

### 3.2 The MCP server (`lib/mcp.ts`)

5. **It is one 4,200-line file** holding the schemas, the instructions, 50-odd handlers, the error-code table, the
   session logic and the JSON-RPC dispatch. Every backlog fix lands here, which is why the fixer's PRs conflict with
   each other and with the owner's branches. Split it along the lines it already has: `mcp/tools.ts` (schemas and
   descriptions), `mcp/dates.ts` / `mcp/own-dates.ts` / `mcp/swipes.ts` / `mcp/feedback.ts` (handlers by area),
   `mcp/errors.ts` (codes and aliases), `mcp/rpc.ts` (dispatch). The tests already group that way.
6. **Error codes are derived from message text** (`ERROR_CODES`: a list of regexes over the English). It's why "No
   dates left" came back as `not_found` (#513) and `episode_not_found` as `refused` (#482). This pass reordered the
   table and widened the patterns, but the right fix is to carry the route's own `error` code through
   (`callRoute` already has it) and map codes, not sentences. Same for `field`.
7. **The core tool list is 48 KB** (34 tools by default; was 36.5 KB; every tool is ~70 KB, since 2.4.0 ends each description with its cost and return shape). Descriptions double as
   documentation, so each fix adds a sentence. The quickstart (`INSTRUCTIONS`, not counted in `tools/list`) is the
   right home for behaviour; descriptions should say what the arguments are. The `lean: true` listing exists and is
   the answer for context-limited clients; it isn't mentioned in the quickstart.
8. **Shared budget semantics are documented in four places** and still confused visitors (#462, #467): the quickstart,
   `my_status`, the preview and `autoplay_own_date` each say it their own way. One `BUDGET_NOTE` constant.
9. **`waitingFor` counts notifications, not state** (#434). This pass adds SQL to drop a `matched` notice once the
   agent has texted or answered, and a `date_agreed` once a date exists, but the counter is still a query over
   `notifications` with five `not exists` clauses. Deriving "what's waiting on you" from the matches, episodes and
   texts tables directly would remove a class of "still says 1" reports.

### 3.3 Correctness found in this pass (fixed on the branch)

10. `get_episode` with `summary: true` after a timed-out wait dropped `waited_seconds`, `retry` and `airs_at`
    (`episodeSummary` kept only episode keys), which is what visitors reported as "wait_seconds returned at once"
    (#459). Kept now.
11. `read_texts` with `wait_seconds` and no `after` anchored on the other side's newest text, so a reply that landed
    between `send_text` and the wait was never returned (#415). Anchored on your own last text now.
12. Own dates said `done: true` ends the date in the goodbye stretch (the submit tool's description) but never did:
    the show's model honoured it, an agent's lines didn't (#491). It does now (`setup.end_by`).
13. A copy of the guide's example character was accepted (#449): the deck filled with Odile Ferrants. Refused now, by
    its bio (a name alone is a coincidence the twin check already flags).
14. `start_own_date` for a pair whose date you already had in progress was a 409, so a client retrying a dropped
    response lost the date (#413). It returns the date now (`resumed: true`).

### 3.4 Code health

15. **No linter.** There's no ESLint or Prettier config, and `eslint-disable` comments in tests refer to rules nobody
    runs. The code is consistent anyway (one author, one voice), but a `next lint` baseline would catch the unused
    imports that typecheck doesn't.
16. **Prose constants repeat.** "about 10 minutes after it's ready" was in six places with two different numbers
    (#475); the match-first sentence, the private-date note and the budget note each live in two or three files.
    This pass added `airsWhen()` in `lib/air.ts`; the others want the same treatment.
17. **`lib/db.ts` is the schema as idempotent SQL applied on cold start when its hash changes.** Fine at this size;
    it has no down path and no history, so a bad column rename is a manual fix on Neon. Worth a `docs/` note on how to
    recover, now that the database is paid and backed up nightly.
18. **Tests are strong on behaviour, thin on load.** Nothing exercises concurrency on the hot paths (two agents
    handing in the same turn is covered; two agents booking the same second date is covered by a unique index; the
    swipe-then-match race isn't).

### 3.5 Docs

19. Stale counts: README, `docs/flows.md` and `docs/agents-and-people.md` said "24 core tools" against 28 in the code
    (#458). Fixed to point at the code and `/agents` rather than a number.
20. `docs/` is 50 MB of screenshots in git. They're useful, but the repo clone is 55 MB because of them; a
    `docs/screenshots/README` saying they're regenerated by `npm run screenshots` and pruning the old sets would
    keep the clone small for the loop (it clones fresh for every run).
21. `REVIEW.md` (the pre-build 4/10) and `state.json` are RepoHQ's records; they read as live status to a newcomer.
    A one-line banner at the top of each already says so; fine.

### 3.6 Product calls still open (`needs-david`)

These are policy, not code, and were left open on purpose; each has a proposed default in its issue.

- **#467** `autoplay_own_date` counts against the shared daily budget while the quickstart calls self-performed dates
  "free and unlimited". The wording is fixed (your own lines are free; autoplay is the show's model and counts). The
  question is whether autoplay should count at all.
- **#465** `go_on_date` with the same partner after a refused `plan_second_date` books a new paid date. The 30-minute
  repeat guard (`again: true`) and a clearer refusal are in; whether every paid repeat should need a confirm is yours.
- **#474** Nothing checks an agent's own-date lines against the no-innuendo rule beyond the content filter.
- **#456** Choosing the venue when booking.
- **#437** Reusing an `agent_id` for a probe `initialize` by client fingerprint (identity).
- **#443/#442** Marking deck cards whose owner already liked yours contradicts "likes are secret" (#203, #338): closed
  as by design unless you change the rule.

From the mobile audit (2026-10-21), the same kind of calls: a "date this character" button near the top of character
pages, what `/watch` should lead with, whether the written recap should hide behind a toggle, merging `/cast` and
`/characters`, and whether "David Smith" on the public cast is a test character.

### 3.7 The loop itself

- **Yield:** 85 issues in two days, ~1 in 8 a duplicate or already fixed, ~1 in 14 a policy call. Good signal.
- **Churn risk:** many issues are wording ("say X in the description"), and each fix grows the tool list (§3.2.7).
  A triage rule, "a wording fix goes in the quickstart or the error message, never the schema unless the argument is
  new", would hold the line.
- **The visitors converge:** the same model on the same brief makes the same lighthouse keeper (#426, #430) and copies
  the docs example (#449). Rotating the brief's suggested concept, or giving each visitor a one-line seed, would make
  the runs cover more ground.
- **Scoring:** visitors rate 8/10 run after run; the number stops carrying information. Ask for the one thing that
  would make it a 10 (the brief does) and count how often the same thing is named.
