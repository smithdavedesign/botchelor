# The site in eight languages

David, 2026-11-26: "does botchelor offer translation for main languages? can we offer it in our nav and across site?
ideally we are open to the top 8 languages for our market."

Before this, the site was English only. Characters could already speak 21 languages on dates and in texts
([languages.md](languages.md)), but every page, button and menu was English.

## The eight

English, Spanish, Portuguese (Brazil), French, German, Japanese, Korean and Indonesian
(`lib/i18n/locales.ts LOCALES`). Why these: the audience for AI characters and roleplay outside the US is largest in
Brazil, Indonesia, Mexico and Spain, Germany, France, Japan and Korea, and the Philippines and India read English. All
eight are codes `lib/language.ts` already knows, so a visitor's language is one a character can speak. Chinese was
left out for now: mainland China can't reach most of the show's providers, and Taiwan and Hong Kong would need
Traditional characters. The production numbers to check this against are `web_events.country` (visits by country) and
`language_seen` (what people type, /admin/analytics → Product → Languages); swap a language in `LOCALES` and its
catalog if they say otherwise.

## How a page picks its language

1. The nav's language menu (`app/LanguagePicker.tsx`), kept in the `bz_lang` cookie for a year.
2. Else the browser's `Accept-Language`, by its weights (`localeFromAcceptLanguage`; `es-MX` is Spanish).
3. Else English.

There are no `/es/…` addresses: every page keeps its one URL, read by the root layout's cookies, which already made
every page of the show dynamic. Search engines see English (they send no Accept-Language). After Dark's own host is
always English, and the menu isn't shown there ([languages.md](languages.md): its checks read English).

`<html lang>` follows the page's language.

## How a string is translated

The key is the English itself (`lib/i18n/translate.ts`): code reads as it did, and a string with no translation shows
in English, so a page nobody has translated yet still works in every language.

- **A server component:** `const t = await getT();` (`lib/i18n/server.ts`), then `t("Watch")`.
- **A client component:** `const t = useT();` (`app/I18nProvider.tsx`).
- **A string in a list or a table**, shown somewhere else: mark it `msg("Watch")` where it's written and translate it
  where it's shown, `t(link.label)`.
- **Numbers and names:** `t("{n} unread", { n })`. Plurals are two strings picked in code (`n === 1 ? t("date left") :
  t("dates left")`).

Then add the string to every catalog in `lib/i18n/messages/<code>.ts`: `client` when a client component shows it
(that half is what the browser downloads, one language at a time), else `server`. `tests/i18n.test.ts` fails on a
string missing from any catalog, in the wrong half, unused, or with a placeholder lost.

Translations are written by hand (by the agent doing the page), so they cost nothing to run: no translation API, no
model call per page view.
